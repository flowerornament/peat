# peat — build spec (v1, hackathon afternoon)

Agent memory as a fold. Agents deposit events (mechanical session exhaust + small
observations); every readable surface is a materialized bogkit/fold view. Two goals,
asymmetric effort:

1. **Capture everything we can at session end** — built solid, schema-disciplined.
   The ledger is the investment; you only get one chance to record a session.
2. **Experiment with constructing a session-start prompt** — built disposable.
   `peat brief` is a thin renderer over views; iterating on the prompt means editing
   a template, never the pipeline.

Hackathon category: **agent context support**. Ships as `examples/peat` in a fork of
`flowercomputers/bogkit`, PR to upstream.

---

## 1. Crate layout

```
examples/peat/

  src/main.rs           # clap CLI: capture | obs | brief

  src/pipeline.rs       # the fold pipeline + open() helper
  src/transcript.rs     # Claude Code transcript JSONL -> Vec<(EventId, Event)>
  src/brief.rs          # view reads -> BriefJson; template rendering
  brief.tmpl            # the session-start prompt template (checked in, hot-editable)
  hooks/                # example .claude/settings.json hook snippets + obs guidance
```

Dependencies beyond workspace crates: `serde`, `serde_json`, `clap` (derive),
`minijinja` (or hand-rolled `{section}` substitution if deps are a pain — template
logic must stay trivial).

## 2. Event model (src/event.rs) — versioned, append-forever

```rust
/// Bump when the enum changes shape. Replay-from-genesis means every event ever
/// written must parse forever: additive evolution only, or match on version.
pub const EVENT_VERSION: u16 = 1;

pub type SessionId = String;           // Claude session uuid
pub type EventId = (SessionId, u32);   // (session, seq). seq = transcript entry index
                                       // for Did; 100_000+ for Obs. Idempotent upsert.

#[derive(Clone, Serialize, Deserialize)]
pub struct Envelope {
    pub v: u16,          // EVENT_VERSION at write time
    pub ts_ms: u64,      // FROM THE TRANSCRIPT/CALLER — never wall clock at fold time
    pub session: SessionId,
    pub kind: Event,
}

#[derive(Clone, Serialize, Deserialize)]
pub enum Event {
    // ---- mechanical exhaust (cannot lie) ----
    SessionMeta { cwd: String, branch: Option<String>, ese_version: String },
    UserMsg    { text: String },                     // what was asked
    ToolCall   { tool: String, detail: String,       // detail: cmd line / file path, truncated 500B
                 ok: bool },
    FileTouch  { path: String },                     // from Edit/Write tool calls
    Commit     { hash: String, message: String },
    FinalMsg   { text: String },                     // agent's last assistant message — free summary
    Compaction {},
    // ---- the one judgment step ----
    Obs        { subject: String, text: String,
                 derived_from: Vec<u32> },           // seqs of Did events cited; may be empty
                                                     // (empty = visibly a bare assertion)
}
```

Rules:
- `SessionMeta.ese_version`: embed `env!("CARGO_PKG_VERSION")` of ese + its feature dims.
  Replay/brief warns (v1) or refuses (later) if the running binary's ese differs —
  `--asof` over re-embedded text with a different model is a plausible wrong answer.
- **No wall-clock reads anywhere in the fold path.** All time comes from events.
- Deterministic fold: anywhere we drain a HashMap in a step/commit we control, sort
  keys first (fold's own operators are fine; this rule is for OUR aggregate step fns
  and brief assembly).

## 3. Pipeline (src/pipeline.rs)

`KeyedStream<EventId, Envelope, _>` at `<repo>/.peat/db` (path from `$PEAT_DB` or
walk up to repo root; `.peat/` in `.gitignore`).

```
Envelope @ ±1
 ├─ FilterMap(as_did_row) ─┬─ KeyBy(day = ts_ms/86_400_000)
 │                         │    → Aggregate("days", day_step) → Table("days_tbl")
 │                         │      DayStats { sessions:i64 (distinct-ish: count SessionMeta),
 │                         │                 tools:i64, fails:i64, commits:i64,
 │                         │                 files: Vec<String> (dedup, cap 20) }
 │                         └─ FilterMap(as_file_touch)
 │                              → InvertedIndex("file_sessions")   // Keyed{path, session}
 ├─ FilterMap(as_searchable) // Obs text AND FinalMsg text AND UserMsg text
 │      Keyed{ key: (session, seq), val: text }
 │      ├─ Bm25("kw")
 │      └─ Map(|d| Keyed(d.key, ese::encode_single(&d.val))) → Hnsw<(String,u32), f32, Cosine, 512>("vec", Cosine, 42)
 ├─ FilterMap(as_obs) ─┬─ KeyBy(subject) → Multimap("evidence")    // subject -> ObsRow, for future `why`
 │                     └─ KeyBy(subject) → Aggregate("subj", subj_step) → Table("subjects")
 │                          SubjStats { latest_text, count, last_ms }   // v1: dumb newest-wins;
 │                                                                      // support semantics deferred
 └─ Table("sessions")  // Keyed{session, SessionSummary{start_ms, end_ms, final_msg, cwd, branch}}
                       // built via KeyBy(session) → Aggregate(session_step)
```

Everything is stock bogkit. **The belief layer with support/flips/Merge/asof from the
design reviews is deliberately deferred** — views are replayable, so deferral is free;
captured events are not, so the schema above gets the care.

The pipeline type can't be named (closures) — follow the examples: helpers that read
the stream are macros, or keep all reads inside `main.rs`/`brief.rs` where the
concrete type is in scope.

## 4. Verbs (clap)

### `peat capture <transcript.jsonl>` (Stop hook)
- Parse Claude Code transcript JSONL (src/transcript.rs). Entries of interest:
  - lines with `"type":"user"` / `"type":"assistant"`; `message.content[]` blocks of
    type `text`, `tool_use` (name + input digest), `tool_result` (error flag)
  - top-level fields: `sessionId`, `timestamp`, `cwd`, `gitBranch`
  - tool_use named Edit/Write/NotebookEdit → also a `FileTouch` (input.file_path)
  - Bash tool_use whose input starts with `git commit` + following result → `Commit`
    (best-effort hash parse; message from `-m`)
  - last assistant text block → `FinalMsg`; `isCompactSummary`/compact markers → `Compaction`
  - **Robustness rule: unknown/unparseable lines are skipped, never fatal.** Capture
    must succeed on a weird transcript. Truncate every stored text field (UserMsg 2KB,
    FinalMsg 8KB, detail 500B).
- One `wtx`; `tx.upsert(&(session, seq), &envelope)` per event. Re-running the same
  transcript is a no-op (idempotent by construction — this is the crash-recovery story).

### `peat obs <subject> <text> [--from seq,seq] [--session ID]`
- Session id from `$CLAUDE_SESSION_ID` or `--session`; ts from `$PEAT_NOW_MS` or the
  CLI's clock (capture boundary, not fold — acceptable). seq = 100_000 + counter read
  from the subjects/evidence view (or just max existing obs seq + 1 for the session).
- Before writing, print near subjects: substring/prefix match over `subjects` table
  keys (v1: no embedding check — Merge events later make drift repairable).

### `peat brief [task words…] [--json]` (SessionStart hook)
- One `rtx` snapshot → `BriefJson`:
  ```json
  { "digest":   { "days": [ {"day":"2026-08-16","tools":214,"fails":6,"commits":11,"files":[…]} ] },
    "last_session": { "ended_ms":0, "final_msg":"…", "branch":"…" },
    "relevant": [ { "text":"…", "kind":"obs|final|user", "session":"…", "age_days":2,
                    "subject":"staging|null", "cited": true } ],
    "files":    [ { "path":"…", "sessions":["s58","s61"] } ],
    "subjects_recent": [ { "subject":"staging", "text":"…", "count":3, "age_days":0 } ] }
  ```
  `relevant` = RRF-fuse `Bm25.search(task, 10)` ⊕ `Hnsw.search(encode(task))`, then
  hydrate. No task words → skip `relevant`, keep the rest. **Every hit carries age +
  kind + citation flag inline** (retrieval-trust rule: hedges are load-bearing).
- Default output: render `brief.tmpl` over BriefJson. Template is the experimentation
  surface — trivial substitution, zero logic beyond section presence.

## 5. Tests (the two oracles — non-negotiable, written first)

1. **Retraction is observable and red-capable**: upsert obs A for subject S; upsert
   obs B (same (session,seq) → replaces A); assert `Bm25.search(A-words)` and
   `Hnsw.search(encode(A-text))` no longer return A's key. Then *temporarily break
   the unlink* (feature-flag or #[ignore]d inverted twin) to prove the test can fail.
2. **Replay determinism**: generate N synthetic events; fold all → snapshot views;
   for k in [0..N] fold prefix k into a temp dir → assert views == views computed
   by an independent scan of the prefix. Property-style over a few seeds.
3. Idempotent capture: capture same transcript twice → identical view state.
4. Transcript parser: golden test against a real (sanitized) transcript checked into
   `tests/fixtures/`.

## 6. Hooks (hooks/README.md + snippets)

```jsonc
// .claude/settings.json (project)
{ "hooks": {
    "SessionStart": [{ "hooks": [{ "type": "command",
       "command": "peat brief \"$(cat)\" 2>/dev/null || true" }] }],   // stdin has hook json; v1 may ignore task words
    "Stop":         [{ "hooks": [{ "type": "command",
       "command": "peat capture \"$CLAUDE_TRANSCRIPT_PATH\" || true" }] }]
} }
```
Exact env/stdin contract for hooks: verify against current Claude Code docs during
setup (SessionStart stdin JSON has `session_id`; Stop has `transcript_path`) — adjust
the snippet to read stdin with jq if env vars aren't provided. Hooks must be `|| true`:
peat failing may never break a session. Also: a short `peat-obs` guidance blurb to
append to CLAUDE.md (emit obs at commits/task-completions, cite seqs when possible).

## 7. Milestones (bead per line)

1. `peat-scaffold` — fork bogkit, `./scripts/new-project.sh peat`, deps, `cargo check`
2. `peat-events` — event.rs + pipeline.rs compile; starter-style smoke main
3. `peat-capture` — transcript.rs + capture verb + fixture test + idempotency test
4. `peat-oracles` — retraction + replay tests (red-capable proof committed in message)
5. `peat-brief` — brief.rs + --json + brief.tmpl + obs verb
6. `peat-hooks` — hook snippets, dogfood on bog-a-thon, capture THIS session as deposit #1
7. `peat-pr` — PR template (category: agent support), demo script

Cut order if time runs out: 6's dogfood polish → obs near-subject printing → digest
files list. Never cut: oracles, idempotency, versioned envelope.

## 8. Invariants (write into .agents/decisions.md)

- The ledger is the API to our past: additive schema evolution only; `v` on every envelope.
- No ambient time or randomness in any fold path.
- Every brief line carries its disposition (age, kind, cited) — rank is not currency.
- The subjects view stays dumb; anything clever must be expressible as a fold over
  events still visible in the raw ledger (future `why`).
- Deferred by decision, not oversight: belief support/flips semantics, Merge{from,to}
  drift repair, --asof replay verb, session fingerprints, `why` verb, multi-writer
  spools. All are replay-backfillable later precisely because capture is total.

## Amendments — 2026-08-16 (setup verification)

1. **Hooks are stdin-JSON only.** No `$CLAUDE_TRANSCRIPT_PATH` / `$CLAUDE_SESSION_ID`
   env vars exist; `session_id`, `transcript_path`, `cwd` arrive as JSON on stdin for
   both SessionStart and Stop (extract with `jq`). SessionStart **stdout is injected
   into session context** — that is the brief delivery mechanism. The session-id
   channel for `peat obs` is a `.peat/current-session` file written by the
   SessionStart hook (there is no other channel available to the in-session agent).
   §6's snippets are superseded by `examples/peat/hooks/README.md` in the fork.

2. **FinalMsg source.** Stop hook stdin carries `last_assistant_message` — the final
   assistant text of the turn, present even when the transcript file lags. `peat
   capture` ingests it as the `FinalMsg` event source when transcript tail parsing is
   ambiguous (accept it as an optional second argument or stdin field; transcript
   tail remains the fallback).

3. *(observed, non-normative)* Transcript timestamps are ISO-8601 strings, not ms —
   `ts_ms` requires parsing; and real transcripts include `attachment` / `mode` /
   `last-prompt` / `ai-title` / `file-history-snapshot` line types beyond
   user/assistant, exercising the never-fatal rule. fold's Hnsw upsert defect is
   fixed in-fork (640ff6f), so §5 oracle 1's Hnsw half runs against patched fold.
