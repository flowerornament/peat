# Changelog

All notable changes to peat. The ledger is the API to our past; so is this file.

Entries prefixed **Hooks:** touch the hook contract. Since 0.4.0 every hook is the constant command `peat hook` and its behaviour ships with the binary, so an upgrade needs no re-sync; before that, hooks were copied bash snippets stamped `hooks snippet vN` and had to be re-copied by hand.

## 0.6.0 — 2026-10-21

- **Hooks: an upgrade's view rebuild never runs inside a hook.** A new view schema used to be rebuilt by whichever command opened the ledger first, which after an upgrade is usually the SessionStart hook: 87 s on a 415 MB ledger, inside the harness's hook deadline, retried on every start once killed. Now a hook that finds stale views prints only the lookup line, says on stderr that the views are rebuilding, and starts the rebuild in a detached `peat` (its stderr appended to `.peat/db.rebuild.log`); concurrent starts share one rebuild. Captures need no special path: the hook already runs them detached, and they wait for the rebuild and land in the rebuilt views, so nothing fired meanwhile is lost (a SessionEnd included). Any other command that finds stale views rebuilds inline as before, one migrator at a time; one that finds another process rebuilding waits up to 10 minutes, then exits 75 (a capture that gives up writes nothing, so the next capture of that transcript redoes it). The detached processes the hook starts no longer inherit the harness's open descriptors. A rebuild killed at any point is either discarded (before it is complete) or finished by the next command (mid-swap); the views are never read half-swapped, and the previous database is still kept at `db.old`. The rebuild also waits for fjall to retire the journal it was written through before swapping: it often closed first, leaving the whole rebuild there (557 MB on murail's ledger), replayed by every later open (12 s for the first session start after the swap, about 5 s for each after) until a large capture checkpointed it. (peat-3bi)
- **An older peat refuses newer views.** A binary that finds views written by a newer peat no longer rebuilds them to its own schema (two versions sharing one ledger used to rebuild over each other on every switch): its hook does nothing but print one line on stderr, and every other command exits 1 naming both view versions and saying to upgrade peat. A process that was waiting for the ledger while a newer peat swapped the views in checks the marker again once it gets the ledger, and refuses then too. 0.5.0 and earlier lack this check, so upgrade every peat that shares a ledger together. (peat-3bi)
- **`peat … | head` ends quietly.** A reader that closes the pipe early used to make peat panic (`failed printing to stdout: Broken pipe`, exit 101); every verb now ends the way a Unix filter does, by SIGPIPE (exit 141), with nothing on stderr. (peat-8dq)
- **Hooks: `peat hook` always exits 0 on a closed stream.** The SessionStart brief, the busy-ledger fallback line and every stderr notice drop write errors instead of panicking, so a harness that stops reading stdout or closes stderr never sees a failed hook. (peat-8dq)
- **Days are your local days, everywhere.** The brief's date was local while its day list, the ladder, `peat <day|week|…>` windows and their counts were UTC days, so late-evening work west of UTC (or early-morning work east of it) showed up on the wrong day: `peat w42` read 0 tools while the brief's today read 101. The fold now buckets activity by UTC quarter-hour and every reading surface regroups those into local days under the UTC offset read at render time; the fold itself still never sees a clock or a timezone. `peat <window> --json` gains `utc_offset_min`, and its `start_day`/`end_day` are local-day indices. The current offset applies to all history, so across a daylight-saving change older day edges sit an hour off. (peat-cgp)
- **One Rust toolchain for the gate, CI and releases.** `rust-toolchain.toml` pins Rust 1.99.1 with rustfmt and clippy; the local `just check` (through rustup), CI and the release builds all use it. CI used to track the latest stable while the local gate ran 1.94, so a lint that only the newer clippy knew (`useless_borrows_in_formatting`) passed `just land` and turned `main` red. The Nix package still builds with nixpkgs' Rust. (peat-36d)
- **Hooks: wired once per machine, not per repo.** `peat hook` is a silent no-op wherever there is no ledger, so its home is the user-level config. `peat hook install` now writes `~/.claude/settings.json`, `$CLAUDE_CONFIG_DIR/settings.json`, the `settings.json` of every live `~/.claude-*` dir (one with `projects/`; backups are left alone), and Codex's `~/.codex/config.toml` (or `$CODEX_HOME/config.toml`), edited in place with its comments and trust records kept. A copied peat snippet is replaced in its own slot, so other tools' hooks keep their Codex trust; peat is recognised only as the program a command runs, followed by a verb a peat hook ran; quoted text counts only as a shell's `-c` script (`/path/to/peat hook` is current; `repeat …` and `say "peat finished"` are not peat). When removing peat from a retired event moves another tool's hook to a new index, install names it for re-trust in Codex's `/hooks`. A file of an unexpected shape, or one peat cannot read, is refused rather than repaired or overwritten. Files are written only when their content changes, atomically, with their mode kept and symlinks followed; a JSON rewrite normalizes key order. `--check` reports drift per file and exits 1 on any; `--print` shows what each file would receive. Upgrading peat stays a no-op for the hooks, and a new repo needs no hook upkeep.
- **Hooks: untracked per-repo copies are removed, tracked ones reported.** Beside the user-level hook a repo's own copy fires a second time (harmless now: see the duplicate guard). Run in a repo, install removes peat from its untracked copies (`.claude/settings.local.json`, an uncommitted `.codex/hooks.json`, …; other tools' hooks kept, a file that held only peat's deleted) and reports tracked ones with the command that removes them, `peat hook install --strip-project`. `--check` lists repo copies as notes, not drift. `~` is never treated as a repo. `--project` (with `--local` / `--codex`) keeps the per-repo form for repos shared with people who lack the user-level hook; `--codex` and `--local` now require it.
- **Hooks: a doubled SessionStart briefs once.** When the same session's start (same id and `source`) fires twice within 10 s, the second prints nothing. The twins run concurrently, so the decision is made under an exclusive lock on a marker in `.peat/fired/`.
- **A fresh ledger's first opens no longer rebuild it.** The view-version marker of a new database was written before `.peat/` existed, so the next open "migrated" the empty db (and concurrent first opens could swap over each other, exit 101). The marker is now written into an existing directory, migrations take a lock so one process rebuilds while the others wait, and a hook whose brief fails in any way prints the lookup line and exits 0.
- **`peat init` opts a repo in.** It creates the ledger at the repo root — in a jj workspace or git worktree, the anchor repo's, which every desk shares — idempotently, and prints where. It is now the one path by which a ledger comes to exist: a read in a repo that never opted in (bare `peat`, `peat obs`, …) exits 1 and says `run peat init`, where it used to create a ledger as a side effect. An explicit `PEAT_DB` is still created on first use.
- **`peat hook install --check` no longer fails for a missing desk skill.** Only `--project` lays the skill in the desk now; a stale copy still fails the check.
- **The skill is user-level, and matches the installed peat.** The nix package ships `share/peat/skills/peat/SKILL.md`, and the home-manager module gains `programs.peat.skill.enable` (off by default, as in anneal, ferry and hail) and `programs.peat.skill.targets` (home-relative dirs, default `[ ".agents/skills/peat" ".claude/skills/peat" ]`; add `.claude-work/skills/peat` and the like per extra Claude config dir), which link that copy, so upgrading peat upgrades the skill. Without nix, `peat skill --user` writes it to every Claude Code config dir and, when Codex is set up, `~/.agents/skills/peat/`, atomically (mode 0644) and one copy per harness: a current copy is kept, a harness whose skill path is or sits in a symlink (home-manager, a `skills/` dir linked into a hub) is left alone, an existing copy is rewritten in place, and only a harness with none gets a new file. `peat hook install` and `--check` report the skill per harness (current, differing from this binary's, or missing with both fixes named) as notes that never fail the check, and never write it. (peat-yjt)
- **Search reads the person's words, not the harness's.** Every user-role message used to be indexed verbatim, so system reminders, hail and tmux-bridge envelopes, skill bodies and slash-command wrappers crowded `peat <words>` and the brief's `relevant` list. Recall now indexes only the person's own words: harness blocks (an allowlist of the tags harnesses inject) are stripped and the typed text after them kept, `<image …>` tags are dropped and the text kept, tags the person wrote (`<ctx>`, `<feedback>`, …) are kept, an envelope that landed mid-message is cut, and a slash command or skill keeps only its arguments. The ledger still holds every message verbatim (`peat <session> <seq>`, `peat events --kind user`). (peat-4p8)
- **The calling session ranks last.** `peat <words>` and the brief's `relevant` list rank hits from the session that is asking after everyone else's and tag them `· this session`; recall `--json` stays an array and gains a per-hit `calling_session` field. The session is known only from exact evidence: `CODEX_THREAD_ID` under Codex (any of Codex's per-process variables means Codex, so an inherited `CLAUDE_CODE_SESSION_ID` is not trusted there), else `CLAUDE_CODE_SESSION_ID`. Hits are demoted rather than dropped because a sub-agent inherits its parent's id, and the parent's earlier turns are exactly what it lacks. When the calling session crowds the candidates, recall widens its keyword fetch once so the result is still full. (peat-4p8)
- **`peat <session>` is a digest.** Besides span, place and closing message, a session's overview now shows what the person asked first, how many tool calls and shell commands it ran and its first failures, the files it edited (with counts), and the commits whose `Session:` trailer names it (read from jj at render time; `null` when the session's repo is unknown). `peat <session> --json` carries the whole digest, every edited file included; every clipped list ends in the command that reads it all. Computed without a model, from events the ledger already held. Codex sessions record no file edits yet. (peat-oqi)
- **The flake advertises its binary cache.** `flake.nix` carries `nixConfig` for `flowerornament.cachix.org`, where CI already publishes every build, so a machine without that cache configured system-wide downloads peat instead of compiling it. (peat-fqw)

Upgrading:

- The views are rebuilt from the ledger once (view schema v4), about a minute and a half on a large ledger; the previous db is kept at `db.old`. When the first command after the upgrade is a session start, that session briefs with the lookup line only while the rebuild runs in the background; run any `peat` read (say `peat subjects`) right after upgrading to pay the rebuild up front instead.
- Run `peat hook install` once on each machine. In a repo that still carries committed per-repo peat hooks, `peat hook install --strip-project` removes them (or keep them: the duplicate guard makes them harmless). On Codex, trust the user-level hooks in `/hooks`.
- Install the skill once per machine: `programs.peat.skill.enable = true` under home-manager, else `peat skill --user`. Desk copies (`.claude/skills/peat`, `.agents/skills/peat`) left by earlier installs can be deleted where a repo does not commit them.
- Repos that already have `.peat/db` need nothing. A new repo is recorded after `peat init`.

## 0.5.0 — 2026-10-18

peat is now the record of what agents did, answerable from whatever an agent is already looking at; it no longer writes a reading of the past into agent context. Reasoning and evidence: `.design/2026-10-19-peat-is-the-record.md`.

- **`peat <ref>`: from a commit, bead or file to the conversation behind it.** A commit or jj change id resolves through a read-only `jj log`: the description's `Session:` trailer (written by a repo's jj-identity SessionStart hook, beside `Jj-Workspace:` and `Agent:`) names the session; without one, the commit's `Jj-Workspace` and committer time are matched against the session whose cwd is that workspace and whose active span contains the time. A bead id resolves by text search, a file path through the file-touch index. The answer is the session(s) and the moment — the person's messages around it and the agent's closing message — each ending in the command that reads the whole thing, plus a `peat asof <date>` handle.
- **The distiller is gone.** `peat distill`, day and window digest paragraphs, and `peat rulings` are removed, along with the `.peat/memory` sidecar and the `.peat/distill` / `.peat/distill-off` markers. A summary pushed into every session anchors a later model on an earlier reading, and a model-kept register of the person's instructions drifted from what the person said. No ledger ever held distilled events, so nothing migrates; the schema stays v3 and the `Distill`/`Lane` variants stay in the decoder, frozen.
- **Commits are no longer guessed from command text.** Capture stopped writing `Commit` events from `git commit` / `jj describe` tool calls: they held shell fragments and, under jj, never a hash (herald: 186 events, 0 hashes). Old `Commit` events still parse. Commits are now read from the repository itself, by `peat <ref>`.
- **The dashboard is for humans.** Bare `peat` and `peat brief` keep sessions active in the last hour, recent days, the ladder, the last closing message and recently touched files; they no longer show rulings, digests, current understanding or commit counts (commit counts came from command-line guesses; commits are read from jj now). Observation anchors print only the commit they were made against (`@abc1234+`); the `~N commits since` figure, which depended on those guesses, is gone. Observations appear only when asked: `peat subjects`, `peat <subject>`.
- **Hooks: the SessionStart injection is two things.** This desk's previous closing message, when that session is not the one starting and ended within three days, and one line on how to look things up (`peat <commit|bead|file|words>`). It replaces the ~2k-token brief: no counts, no rulings, no current understanding.
- **Hooks: four events.** `peat hook` is wired to `SessionStart`, `Stop`, `PreCompact` and `SessionEnd`. `UserPromptSubmit` (prompt-time push, `.peat/push`) and `PostToolUse` are retired; `peat hook install` removes peat from them, and `--check` expects the four.
- **The peat skill is rewritten** for looking things up: a commit you are about to change, a bead you are picking up, a file, "why is it like this", and how far to trust what comes back. `peat obs` stays, for hard-won claims that outlive the work.

Upgrading:

- Run `peat hook install` once per desk (`--local` where the hooks live in `settings.local.json`, `--codex` for Codex) to drop the retired events and refresh the skill. On Codex, review and trust in `/hooks` if it asks.
- `.peat/memory/`, `.peat/memory.mark`, `.peat/distill.lock`, `.peat/distill`, `.peat/distill-off`, `.peat/push`, `.peat/pushed-*` and `.peat/nudged-*` are unused; delete them.
- `peat <commit>` needs jj on `PATH`. Commits without a `Session:` trailer resolve by workspace and time only where the repo's descriptions carry `Jj-Workspace:`.

- **No git where jj owns the tree.** In a jj workspace there is no `.git`, so git walks up to whatever repo encloses it (often `~/.git`) and answers about that. `peat obs` now stamps its basis from the nearest repo root: jj's `@-` and whether `@` has changes where `.jj` is nearest, git's `HEAD` only in a git-only repo, never an enclosing one. `scripts/release.py` refuses to run anywhere but the colocated checkout, refuses when jj's and git's `main` differ (run `jj git fetch` there), tags the commit jj names, pushes `release` with a lease on the tip it observed, and strips `GIT_DIR`-style variables from every subprocess. The Nix cache workflow builds the commit that was pushed, not whatever `release` points at when the job starts. (peat-520.5; reported by andon-1b)
- **`just land` puts the bookmark back when the push fails,** so a rejected push no longer leaves local `main` ahead of the remote and every later land refusing. (peat-o4i)

## 0.4.0 — 2026-10-07

v0.4.0 and v0.4.1 were tagged on 2026-10-06 and withdrawn the same day; this is the 0.4.0 that replaces them. Nothing either wrote reached a shared ledger.

- **Memory is written from what the harness already wrote.** Agents rarely write their own memory well (an audit of two busy ledgers: 1,052 observations, 8 cited, mostly status), and Claude Code already summarizes at every compaction. So `peat distill` takes, for each **closed local day**, the person's own messages, the real compaction summaries, each session's closing message and the commits, and makes one model call that writes a paragraph for the day plus any **standing rulings** the person gave. Each ruling is attached in code to the person's message that carries its words, and dated by it; a ruling no message carries is discarded, and a withdrawal must name the ruling it removes. Weeks, months, quarters and years merge the days. Agent narration and messages between agents are left out: they are most of a day's text and little of its meaning. Reasoning and evidence: `.design/2026-10-07-distill-reads-the-harness.md`.
- **What the distiller writes lives in a memory sidecar, `.peat/memory`, never in the ledger.** The ledger stays at schema v3, so any peat can still read it and a downgrade loses only model work. In the sidecar, a newer deposit supersedes an older one, the trail keeps both, and `asof` reads it up to its cutoff.
- **The brief says the past in words.** It opens with the standing rulings (each ending in the command that shows the message it restates), and any day or ladder band with a digest prints it, keeping the counts as a suffix. `peat rulings` prints the register (`--all` adds withdrawn and superseded entries).
- **Hooks: distillation runs at session start, on your subscription.** `SessionStart` (which also follows every compaction) detaches a sweep that runs only when some session has grown since the last complete run, distills at most 12 calls' worth, and leaves the day in progress alone; `touch .peat/distill-off` pauses it. The model command is `claude -p` with tools, settings and session persistence off and **no model named**, so it runs on the model you chose in Claude Code and follows new releases; `ANTHROPIC_API_KEY` is removed from its environment, so it never bills the API. A first line in an untracked `.peat/distill` replaces the command. On an existing ledger the first sweeps work through the last 14 days, at most 12 model calls per session start and one distiller at a time, on your plan's usage; `peat distill --since N` backfills further by hand.
- **Hooks: the observation nudges are gone.** peat no longer asks agents to deposit observations at the first prompt, after commits, or after compaction; `PostToolUse` is no longer installed. `peat obs` remains for the rare rule nothing else would carry.
- **Hooks: push at the prompt, opt-in.** With `.peat/push` present, `UserPromptSubmit` injects up to three past lines that the keyword and vector lanes both match, from other sessions, once each.
- **Codex compactions no longer store the session's opening prompt as a summary.** Codex encrypts its compaction summary; capture fell back to the first item of the replacement history, which is the opening prompt. Existing ledgers keep those events, and the distiller ignores them (herald held 2,757 of them against 97 real summaries).
- **Hooks: one verb. `peat hook` replaces every copied bash snippet.** Each of the six hook moments used to be a distinct block of `jq` / `nohup` / `sh -mc` shell, copied per project and then patched per desk with `PEAT_DB` anchors and `READY` gates — six blocks, two fabrics, and a `/hooks` re-trust on Codex after every release. The harness already names the moment in the stdin JSON (`hook_event_name`), so one command can serve them all: `peat hook` reads stdin, dispatches, and does in-process what the shell did — writes the session id, prints the brief (lock wait capped at 15 s), emits the once-per-session and post-commit nudges, and detaches captures with the closing message passed as argv, never re-quoted. `peat hook install [--codex|--local] [--check|--print]` merges the wiring into the harness config, keeps other tools' hooks, and strips legacy peat snippets (the `bd setup claude` shape). The `READY` gate becomes its inverse, `.peat/off`; a desk with no ledger is a silent no-op. Existing installs: run `peat hook install` once per desk (`--local` where the old hooks lived in `settings.local.json`, `--codex` for Codex, then one last `/hooks` trust).
- **A peat skill, shipped in the binary.** `skills/peat/SKILL.md` is the judgment half the hooks cannot enforce: read the brief before acting, how far to trust a cited vs uncited line, and what not to do. `peat hook install` lays it at `.claude/skills/peat/` (`--codex`: `.agents/skills/peat/`) beside the hooks, `--check` reports staleness, and `peat skill` prints it. Under 4 KB; it defers the surface to `peat --help` and the handles every line already ends in.
- **Worktrees find their anchor without a redirect.** A git worktree (`.git` file) or secondary jj workspace (`.jj/repo` file) with no ledger and no `.peat/redirect` resolves to the main checkout's `.peat/db` when it exists. Desks Claude Code creates under `.claude/worktrees/` — which used to need a hardcoded `PEAT_DB` in the hook — now remember into the shared ledger with no setup. Explicit `PEAT_DB` and `.peat/redirect` still win.
- **A ledger can no longer be held forever by a capture that never exits.** A detached 0.3.0 capture sat 22 hours holding murail's ledger lock: fjall's database drop sends a blocking close on a bounded channel, and if the channel is full when the last worker exits it parks forever. Opening the ledger now returns a handle whose drop closes under a 30-second watchdog and exits cleanly if the close hangs — commits are already durable at the end of each write transaction. fjall 3.1.12 still has the race, so the watchdog stays. (peat-izh)
- **On a shared ledger, "last session" is this desk's.** The brief used to show the newest closed session from any desk, so one seat resumed from another's summary. It now prefers the newest closed session under the current desk, and labels a fallback "last session on another desk". `--json` gains `where` and `here`. (peat-66g)
- Dependencies: semver-compatible `cargo update` (fjall 3.1.12, lsm-tree 3.1.10, clap 4.6.7, …). The bogkit pin is unchanged.

## 0.3.0 — 2026-09-02

- **The vector lane no longer rebuilds an index per process.** fold's Hnsw sink keeps its graph in memory and rebuilt it from the persisted rows on first use in every `peat` invocation — O(n log n) before any O(1) work, measured at 8.9 s for 7,369 vectors and linear in n, so `obs`, `recall`, and `brief <words>` all paid it (wake briefs, which don't embed, did not). The lane is now an exact scan over the same persisted rows (`fold::terminal::search::Flat`, new in the bogkit fork): 0.1 ms of arithmetic at that size, ~1 ms at 50k, with reading the rows as its only real cost. Rows are byte-identical to the old sink's and the keyspace is unchanged, so **no view rebuild happens** — existing ledgers are read as they are (tested: the new sink reads and deletes rows the old one wrote). Results are now exact and order-independent rather than approximate, which makes `asof` stricter. A trip-wire in `recall` names the successor design when a ledger passes 100k vectors; see `.design/2026-09-02-vector-index-flat-then-graph-in-store.md` for the measurements, the six designs compared, and the store-resident graph this is layer one of.

## 0.2.4 — 2026-09-01

- **Captures no longer force a corpus-sized flush on every turn (snippet v6).** Each `peat capture` unconditionally checkpointed, and a checkpoint rotates the memtable and *waits* for a flush that rewrites index structures sized by the whole ledger — not by the delta. On a 326 MB / ~67k-event shared ledger that meant a `Stop` hook ingesting a 15-line delta sat over seven minutes inside fjall's `rotate_memtable_and_wait`, holding the write lock and visibly freezing the session (caught live: 0 % CPU, lock held, stack in `rotate_memtable_and_wait`). Capture now folds the journal only when the work justifies it — a bulk ingest, or a journal grown past ~48 MB — and otherwise lets the journal absorb the write, which is what the next open replays anyway. The tradeoff is deliberate and documented: an un-folded capture is durable across process exit but not across power loss.
- **Every capture hook is now detached, including `Stop`.** No hook waits on a capture any more, so even the rare fold happens where nobody is watching; hooks return in ~30 ms. The closing message reaches the background process through the environment rather than being re-quoted into a command string — a hostile final message (quotes, backticks, `$VAR`, backslashes) now round-trips byte-exact, which the tests assert.
- **`peat compact`** forces a fold deliberately, for after a large backfill. Routine use should never be necessary; folding is automatic.

## 0.2.2 — 2026-08-24

- **Hooks: salvage captures now detach, and lock waits are bounded (snippet v4).** A `SessionEnd` or `PreCompact` capture used to hold the session open for the length of the capture — seconds, for a transcript peat had not seen before — so a harness tearing down a session would abort it with `Hook cancelled`. Both salvage hooks now spawn the capture detached and return in ~10 ms; the work completes in the background. The synchronous hooks additionally cap `PEAT_LOCK_WAIT_SECS` (15 s for the wake brief, 20 s for `Stop`), below any plausible hook deadline, so contention on a shared ledger skips quietly instead of surfacing as a cancelled hook. **Re-copy the v4 snippets from `hooks/README.md`** (and on Codex, re-trust them afterwards). Nothing was lost to the old behaviour: capture is idempotent, and `peat capture <transcript>` recovers any tail that was cut short.

- **Hooks: Codex hooks do nothing until you trust them — documented.** Codex gates every non-managed command hook behind an explicit review and records trust against the hook's exact text; an untrusted hook is skipped silently, with no error and no ledger entry. Copying `.codex/hooks.json` therefore installs nothing that runs: you must also run `/hooks` in the Codex CLI to review and trust it, per project, and again after **every** re-sync this changelog asks for, because editing a hook's text marks it for review again. `hooks/README.md` gains a "Codex: hooks must be trusted before they run" section with the two gates (project trust, hook trust) and a fire-don't-read verification recipe. No snippet changes — the v3 stamps still stand.

- Codex parity is now verified end to end against 0.149 rather than read from its source: a live session confirmed the documented stdin fields arrive and that `SessionStart` stdout is injected into the Codex model's context (the model read back a marker that existed only inside the injected brief). Noted for later: Codex has a dedicated `PostCompact` event that could carry the post-compact deposit nudge, which is dormant there today because its `SessionStart` has no `compact` source.

## 0.2.0 — 2026-08-20

- **Observations carry their basis, not just their age.** Every `peat obs` now stamps the repo state it was deposited against — commit hash of `HEAD` in the depositor's cwd plus a dirty-tree flag — by construction, with no opt-in surface to forget. Subjects, brief, evidence trails, and recall hits render the anchor inline (`@abc1234+ · ~4 commits since`; `+` means the tree was dirty), so a durable rule is distinguishable from a snapshot that has since rotted. The commits-since figure is a read-time join over the day table — no git and no wall clock in any read path. Event schema is now v3 (`Obs2`); every pre-v3 observation parses forever and renders unanchored.

### The tool

- **Capture**: session transcripts (Claude Code JSONL and Codex rollouts, auto-detected) ingest into one append-forever ledger — idempotent by `(session, seq)`, never-fatal on unknown lines, incremental via a per-transcript cursor so re-capture costs O(new lines).
- **Observations**: `peat obs` deposits one judged claim; near-subject hints, citations via `--from`, backdating via `--at`.
- **Reading, dispatched by shape**: bare `peat` orients (digest, active sessions, temporal ladder, beliefs); `peat <window>` zooms (w33, 2026-07, q3, ranges); `peat <session>` overviews; `peat <subject>` reads a full evidence trail; anything else searches (BM25 ⊕ HNSW, reciprocal-rank fused). Every line of every read ends in the exact command that goes one level deeper.
- **The temporal ladder**: the brief covers the entire past in bounded lines — calendar bands widening geometrically with distance, computed at read time from the materialized day table. `--budget` re-slices; nothing is stored or recomputed.
- **Time travel**: `peat asof <date>` replays the ledger prefix through the same deterministic pipeline — the truth of that day, oracle-tested.
- **Hooks**: full session-moment coverage for Claude Code and Codex (brief at start, capture at stop/compact/end, one observation prompt per session). Multi-agent: many worktrees, one memory, single-writer lock with polite retry; `.peat/redirect` points desks at their anchor.
- **Contracts**: stdout is an API (styling only on TTYs, `--json` never clipped); no wall-clock in any fold path; additive-only schema (v2); red-capable oracles (the `--ignored` twin must fail, and CI proves it).
